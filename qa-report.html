Game modes review 3 shipped · 2 placeholders

There is no multiplayer, co-op or realtime play, and that is a deliberate v1 decision rather than a gap. Competition is asynchronous, through the ranked leaderboard. All three shipped modes were playable end to end when this audit began; what follows describes them as they stand after the fixes.

Main Journey — ranked

Routes.gameplay · 100 levels · server-authoritative
Functional

Attempts open server-side, every answer is a separate validated request, and the score is never computed on the client. Timer resets per question; sequence violations resync to the server's index; an offline submit is held and retried with the same payload rather than costing the player the attempt. Failure, timer-expiry, ad-break and IAP paths all exist.

Practice — offline

Routes.practiceGameplay · gzipped content pack
Functional

Downloads and caches a content pack, plays without a connection, and refuses levels the pack does not cover with a specific message rather than an empty screen. Result screen steers back to ranked play when the level is unlocked there.

Kids Zone — adventures

Routes.kidsZone · 4 adventures · 16 stops · 12 distinct engines
Functional

Creation Garden, Battle of Siddim, Noah's Ark and Baby Moses each run an animated intro plus three levels on purpose-built engines — archery, ark-building, animal care, a river runner, a plague-ordering puzzle and a sea-crossing rhythm game. Content-safety substitutions are handled thoughtfully and documented.

Every layout failure in this report lived here, and all of them are now fixed and pinned by a 108-case suite. Stars persist per stop, so finishing one leaves something to come back and beat; the zone locks itself to portrait; and its music and narration stop when the app does.

Heroes Path · Wise Kings

kids_zone_adventures.dart · 1 stop each
Placeholder

Both are labelled "Coming soon" but render in the hub as ordinary, tappable adventures backed by the generic explorer and storyPath mini-games. A child who taps them gets a real but empty-feeling game rather than a locked door. Both now lay out correctly at every size — kings_1 was among the worst offenders, overflowing by 509 px at large text — but laying out correctly and being worth opening are different things, and these are still placeholders.

Multiplayer / co-op / realtime

out of scope for v1
Not built

Documented as out of scope: requirements.json records realtime as "not required". The ranked leaderboard is therefore the only social surface. Its three-minute refresh used to run for the life of the app; it now follows the visible tab and the app lifecycle (finding J4).

Critical — blocks a store release

C1Fixed

A release build with no --dart-define ships pointing at a developer laptop

lib/core/config.dart:24–28

apiBaseUrl falls back to http://10.0.2.2:8000 on Android and http://localhost:8000 elsewhere, with no kReleaseMode guard. Any release built without API_BASE_URL set is a fully installable app in which sign-in, the level map, ranked gameplay, the leaderboard and IAP entitlement all fail. The URL is also cleartext, which Android blocks by default from API 28 — so the failure is silent and total rather than partially working.

Shipped 10 Sep 2026AppConfig.releaseConfigErrors refuses a release build that was never pointed at a backend, or pointed at one over plain HTTP, and main() throws on it before the first frame — ahead of CrashReporting.runGuarded, so it fails loudly rather than being swallowed by the very handler meant to report it. Empty in debug and profile, so the loopback defaults keep working as the development convenience they exist for.
C2Fixed

Android release is signed with the debug keystore

android/app/build.gradle:45–48

signingConfig = signingConfigs.debug, with the scaffold's own TODO still in place. Play will reject the upload. The release block also has no minifyEnabled, shrinkResources or ProGuard rules, so the shipped APK is unshrunk and unobfuscated.

Shipped 10 Sep 2026A real signingConfigs.release now exists — it did not before, which mattered more than it looked: the build referenced it behind an if key.properties exists branch, so the reference was unresolvable but masked while the file was absent, and would have failed at configuration time the first moment anyone tried to sign for real. It reads android/key.properties (gitignored, with a committed .example) and names any missing key. minifyEnabled, shrinkResources and a proguard-rules.pro are wired. Verified by building: R8 and resource shrinking ran clean, and apksigner confirmed a release APK signed with a throwaway certificate rather than the debug one — then the test credentials were removed.
C3Fixed

Both platforms carry Google's sample AdMob application IDs

android/app/src/main/AndroidManifest.xml:35 · ios/Runner/Info.plist:48

ca-app-pub-3940256099942544~3347511713 and …~1458002511 are the public test IDs. Shipping them means no revenue and a policy problem. iOS additionally has no SKAdNetworkItems array, so ad attribution would not work even once the real ID is in.

The runtime ad gating itself is sound: an under-13 account never initialises the SDK, the server withholds the unit IDs independently, and child-directed treatment plus a G content rating are set before initialize(). The problem is only the IDs.

Shipped 10 Sep 2026Android now takes the AdMob id from -PadmobAppId as a manifest placeholder, and a Gradle verifyReleaseConfig task fails assembleRelease and bundleRelease while it is still Google’s sample — the same fail-at-build-time shape as C1’s Dart guard. iOS has no equivalent hook, so its id, the SKAdNetwork list and the distribution identity are carried by a written checklist instead. ITSAppUsesNonExemptEncryption and Google’s own SKAdNetwork id were added. The real ids are account secrets and are still not in the build — what changed is that shipping the samples is now something the build refuses rather than something nobody notices.
C4Fixed

The toolchain predates current Play submission requirements

pubspec.yaml:11 · flutter 3.24.5 (13 Nov 2024)

targetSdk resolves to Flutter 3.24's default of 34, and 3.24 does not emit 16 KB-page-aligned native libraries. Both are hard gates on current Play uploads. This is not a code change — it is an SDK upgrade with a regression pass behind it, so it needs scheduling now rather than at submission.

Corrected 10 Sep 2026 — this finding was over-calledThe targetSdk half was real and is fixed: it is pinned to 36 rather than inheriting Flutter’s 34. The 16 KB half was wrong. The claim that Flutter 3.24.5 cannot produce 16 KB-aligned libraries was reasoning from the SDK’s age rather than from the build, and the build disagrees. Measured on the actual release APK: every native library passes, libflutter.so at 64 KB alignment and the rest at 16 KB. Checked twice by different means — ELF program headers parsed directly, then confirmed with the NDK’s llvm-readelf (0x10000, 0x4000) — and the packaging side confirmed with zipalign -c -P 16, which reports every .so stored uncompressed and page-aligned: Verification successful. No SDK upgrade is required to ship. Upgrading from a November 2024 toolchain is still worth scheduling as maintenance — and targetSdk 36 brings Android 15 edge-to-edge enforcement, which wants checking on a device — but neither is a blocker, and this report should not have said otherwise.
C5Fixed

Kids Zone music and narration keep playing after the app is backgrounded

lib/app.dart:70 · lib/services/kids_zone_audio_service.dart

didChangeAppLifecycleState returns immediately unless the state is resumed — there is no paused or inactive branch anywhere in the app. The looping audioplayers ambience and any in-flight flutter_tts narration therefore continue when the child locks the screen, takes a call, or switches apps. On a children's title this is the kind of thing that draws a store review comment, and it is the single most likely one-star complaint in the build.

Shipped 10 Sep 2026Ambience pauses and TTS stops on paused, hidden and detached. inactive is deliberately ignored — iOS passes through it on the way to hidden, so acting there would stutter the music every time the notification shade is pulled down. The service needed two pause flags, not one: backgrounding stops speech, which completes the speak() the read-aloud button is awaiting, whose finally calls straight into resumeAfterSpeech() — with a single flag, locking the phone mid-narration would have started the music.

Major — ship-visible defects

J1Fixed

21 of 72 Kids Zone render configurations overflow

measured 10 Sep 2026 — see the matrix below

Nothing in the app calls setPreferredOrientations, and both manifests permit landscape on phones, so every stop must lay out at 720×360. Six do not. Four more overflow at 360×720 portrait at default text size — a common low-end Android size — including three of the four adventure intros, which are the first screen a child sees in each world. Eleven overflow at text scale 1.6, well inside the app's own clamp of 2.4 and reachable through the in-app "Large text" toggle.

Shipped 10 Sep 202621 broken frames → 0, measured across a wider matrix than the one that found them: 18 stops × 6 frames, up to the app’s own 2.4 text ceiling. Three shared widgets carry it — the shell’s cue card and action are capped at 38% / 40% and scroll; KidsZoneIntroPanel replaced four hand-built copies of the same broken panel; KidsZoneBoardLayout protects the board and lets the chrome scroll. Fixed-size gauges and controls now scale down rather than out, and the animal emoji is marked TextScaler.noScaling because it is a picture, not text. Kids Zone is locked to portrait — but the landscape overflows were fixed anyway, since the lock is a request large screens can decline.
J2Fixed

Typography is fetched from Google at runtime, so an offline first launch loses the entire visual identity

pubspec.yaml (no fonts: section) · kids_zone_tokens.dart:33 · parchment_codex_tokens.dart:40,58

Nunito, Karla and Cormorant Garamond come from google_fonts with no bundled files and no allowRuntimeFetching = false. On a first run without a connection every screen silently falls back to Roboto — and the Kids Zone documentation's claim that the zone "needs no backend, it is fully offline" is not true of its typography.

There is a second edge here. That fetch is an unsolicited request to a Google host, carrying the device's IP, on first launch — before and independent of the parental-consent gate, on a product whose whole compliance posture is built around not doing that. Worth a look from whoever is signing off the privacy policy.

Shipped 10 Sep 2026google_fonts removed from the dependency tree outright rather than disabled by flag. Only three call sites used it, so deleting the package makes the network path impossible by construction instead of by a setting someone can forget. The 11 static instances the app actually renders are bundled (1.5 MB) and named through AnointedFonts. This closes the offline-launch fallback and the unconsented third-party request together.
J3Fixed

A stale restore timer can resolve a later purchase flow

lib/services/iap_service.dart:225–231

The 8-second fallback that rescues a silent restorePurchases() checks the _pending field, not the completer it was created for. Sequence: a restore fails at 2 s and completes; the user taps Buy at 4 s, creating a new _pending; at 8 s the old timer fires, sees a live pending completer, and finishes the purchase flow with nothingToRestore or alreadyOwned while the store sheet is still open. The user is routed to the wrong screen for a transaction that may still complete. The timer is also never cancelled in dispose().

Shipped 10 Sep 2026The fallback is now bound to the completer it was armed for via identical, re-checked after the serverStatus() round trip — itself a window the flow can move in — held in a field, and cancelled in _completePending as well as dispose. It can no longer outlive the flow it belongs to, whatever resolves that flow.
J4Fixed

The leaderboard polls every three minutes for the life of the app

lib/features/leaderboard/leaderboard_screen.dart:45 · home_shell.dart:66

HomeShell holds the four tabs in an IndexedStack, so the leaderboard stays mounted whichever tab is showing — and the shell stays mounted beneath every pushed route. The timer therefore keeps firing during ranked gameplay, during ad breaks, throughout the Kids Zone, and while the app is backgrounded. It is gated on neither tab visibility nor lifecycle.

Shipped 10 Sep 2026The poll now follows both signals it should always have followed: the shell tells the tab when it is the visible one, and the screen observes the app lifecycle itself. It starts on selection and on resume, stops on deselection and on background.
J5Fixed

Kids Zone progress survives sign-out and account deletion

lib/core/local_store.dart:222–234

clearAccountScopedState() clears the token, cached profile, level map, leaderboard, notification flags, analytics queue and current level — but not kids_zone_completed_stops or the kids_zone_tutorial_* flags. On a shared family device, the second child signs in and finds the first child's adventures already completed and unlocked. It also means a deletion request leaves child-generated play data on the device.

Shipped 10 Sep 2026clearAccountScopedState() now clears the completed stops, the stars, and every kids_zone_tutorial_* key. The install id is deliberately left alone — it is not personal data, and regenerating it would break the abuse controls it exists for. Both halves are pinned by tests.
J6Fixed

Stars are computed, shown once, and thrown away

local_store.dart:207 · every game's _finish()

All twelve engines derive a considered 1–3 star score — archery accuracy and breaches, ark misses, herd happiness, wrong plague attempts, scored sea beats — and the celebration screen displays it. markKidsZoneStopComplete() then persists a bare stop ID. The hub can only ever show n of m done. For a children's game this removes the entire replay loop: there is nothing to beat, and no reason to play a stop twice.

Shipped 10 Sep 2026Best-of-run stars are persisted per stop and rendered on the hub rows — filled for what was earned, hollow for what is still there to go back for. Best rather than latest, so a child who replays for fun and does worse never loses a star they already have.
J7Fixed

Double-tapping "finish" completes a stop twice

river_rescue_game.dart:439 · plague_sort_game.dart:263 · archery_game.dart:462 · animal_care_game.dart:277

The summary card wires onPressed: onFinish with no disable-after-tap, and KidsZoneGameScreen._complete() awaits a write before navigating. Two taps inside that window run the whole path twice: two kids_zone_stop_completed events for one completion, and two pushReplacementNamed calls. Children double-tap. Sea Crossing already guards this with a _finished flag; the other four do not.

Shipped 10 Sep 2026One re-entrancy guard at the router rather than five in the games, which covers all eighteen at once and cannot be forgotten by the nineteenth.

Minor — polish, hygiene, and small correctness

N1Fixed

Page padding is doubled on three screens by an EdgeInsets.horizontal misread

level_map_screen.dart:164,166,189,191,227,229 · kids_zone_hub_screen.dart:117,119 · kids_zone_complete_screen.dart:66

EdgeInsets.horizontal returns left + right, not one side. These call sites feed it back in as a single-side value, so the level map and Kids Zone hub sit at 32 px on a phone and 64 px on a tablet instead of 16 and 32. The completion screen compounds it: ContentColumn already applies the page padding, then an inner Padding adds 32 more. practice_hub_screen.dart:225 divides by two and is the one correct use — which is what makes the inset inconsistent between tabs.

Shipped 10 Sep 2026Layout.pageInset(context) now returns the single number the call sites actually wanted, and all nine use it. Fixing it at the call sites alone would have left the trap in place for the next screen — pagePadding(context).horizontal still reads like "the horizontal padding" and still means left plus right.
N2Open

16 MB of uncompressed WAV for three background loops

assets/audio/kids_zone/*.wav — 3 × 5.3 MB

Three 60-second mono 44.1 kHz WAVs make up essentially the whole asset bundle. Re-encoding to OGG or AAC takes it to roughly one megabyte total at no audible cost, on a product whose audience is largely on entry-level Android hardware and metered data.

Not done — and the advice above was incompleteSource confirmed: three 60-second mono 44.1 kHz 16-bit files, 5.05 MB each. No audio encoder is installed here, and fetching one ran at about 1 MB a minute against an 80 MB download — not a proportionate spend for a minor finding, so it was stopped rather than left running. scripts/encode_kids_zone_audio.py is ready for whoever has ffmpeg. It targets AAC in M4A rather than the OGG this report originally suggested, for two reasons worth knowing before anyone runs it: audioplayers on iOS is AVAudioPlayer, which cannot decode Vorbis at all, and MP3 carries encoder delay the container does not describe, so a track that loops under gameplay gaps audibly every time it comes round. "No audible cost" was too glib — M4A is close to gapless, not exactly gapless, and this is background music that loops for as long as a child plays.
N3Fixed

No RepaintBoundary anywhere in the app

parted_sea_view.dart, moses_scene_view.dart, archery_game.dart (shouldRepaint => true)

The full-screen animated scenes repaint every frame by design, but they share a layer with their HUD, so the score, hearts and buttons are re-rasterised at 60 fps alongside them. The frame loops themselves are well built — a _frame ValueNotifier rather than a per-frame setState — so this is the one cheap win left. Separately, BrandBackground paints four gradient orbs behind every screen and is fully occluded on nearly all of them.

Shipped 10 Sep 2026All seven full-screen animated scenes — the parted sea, the Nile, Egypt under the plagues, the creation world, the Siddim valley, the ark and the Moses intro — now sit in their own layer, so their per-frame repaints stop dragging the HUD along with them. The frame loops themselves needed nothing: they were already driving a ValueNotifier rather than calling setState every frame.

lib/features/shell/home_shell.dart:100–104

Every NavigationRailDestination uses Icons.circle_outlined / Icons.circle. Map, Leaderboard, Practice and Profile are distinguishable only by their labels on the layout where the icons are largest.

Shipped 10 Sep 2026Each destination now has its own outline/filled pair — map, trophy, school, person — so the rail reads at a glance on the one layout where the icon is largest and the label smallest. N5Fixed

Adventure and stop copy sits outside the ARB

lib/features/kids_zone/kids_zone_adventures.dart

The rest of the app is exemplary here — a grep for hard-coded Text('…') across 132 files returns three hits, all numeric interpolation. But every adventure title, subtitle and stop teaser is an English literal in the catalogue, rendered directly by the hub. They are the largest untranslatable surface in the product.

Shipped 10 Sep 2026All 48 strings — six adventure names and subtitles, eighteen stop names and teasers — are in app_en.arb. The catalogue keeps ids, order, colour and which game a stop runs; everything a player reads resolves through kids_zone_strings.dart. Written as switches on the id rather than a map, because l10n.kidsZoneStopArk1Title is a real getter and a typo is a compile error where a string key would only fail on a device — the same reasoning behind plagueNarration. A resolver returns empty for an id it does not know, so a missing string is a quiet gap rather than a crash in a child’s screen; kids_zone_strings_test.dart is what stops that gap ever shipping, asserting every id in the catalogue resolves.
N6Fixed

Eight use_build_context_synchronously sites, one with a real path to it

level_complete_screen.dart:94 · and 7 others

Most are guarded well enough in practice. The exception is the notification opt-in: context.read<LocalStore>() runs after an OS permission dialog and a setOptIn write, with no mounted check, and throws on a deactivated element if the screen goes away in between.

Shipped 10 Sep 2026All eight fixed, not only the one with a live crash path. Every case was the same shape — a context lookup after an await, whether that await was an OS permission dialog, an OAuth round trip, a pushed route or a confirm dialog — so each now resolves what it needs before the await rather than reaching back into a tree that may have moved on. This alone took flutter analyze from 12 issues to 3, and N7–N8 took the rest — which is worth more than tidiness: eight standing warnings everyone has learned to scroll past is how a real one gets missed.
N7Fixed

Store-metadata and manifest gaps

AndroidManifest.xml:4 · ios/Runner/Info.plist

android:label is the lowercase "anointed", so the launcher shows an unbranded name (iOS CFBundleDisplayName is correct). There is no android:allowBackup="false", so the cached child profile and Kids Zone progress go to Google auto-backup. Shipped 10 Sep 2026The launcher name is now @string/app_name — a resource rather than a literal, so a values-xx/strings.xml can localise it the way the rest of the copy now is. Production readiness one gate left, and it is not code

The engineering underneath this was always better than the finding count suggested. Ranked play is properly server-authoritative and never trusts the client with a score; the offline paths are real rather than aspirational; the ad gate is two independent barriers, not a flag. What was missing was the last mile — lifecycle handling, layout under conditions nobody tested, and release configuration. All three are now closed, and the build enforces the third itself rather than relying on anyone remembering it.

What is left

Nothing here blocks a submission.
